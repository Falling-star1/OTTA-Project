## 已通过和未执行的部分

- 代码版本匹配，运行的是预期v3候选包。
- 程序先执行损失对比，再执行逐参数梯度对比。日志停在梯度断言，说明本次损失对比已在设定容差内通过；具体损失值未在失败收据中完整保存。
- GPU梯度一致性没有通过。检查遇到第一个不满足容差的张量即抛错，尚未收集全模型相对L2误差、方向相似性等诊断。
- 16步Trainer保存恢复测试尚未开始，没有相应检查点，也没有最终PASS收据。
- 两个诊断进程均已退出，GPU6、7在核查时空闲。这次没有启动5000条训练或评测。

CPU BF16检查通过与GPU FP16失败并不矛盾：硬件、精度和矩阵规模不同。CPU结果不能代替3B模型在2080 Ti上的数值检验。

## 后续需要定位什么

保持本次失败记录，不修改现有权重或删除梯度门禁。下一轮有限诊断应先收集数据，而不是直接调宽容差：

1. 保存每个LoRA参数张量的参考/分块梯度范数、差值范数、相对L2、方向相似性、符号差异和近零元素比例，同时保留逐元素检查结果。
2. 在同一权重、同一输入、同一AMP上下文下，分别比较单投影块和多投影块；区分head分块累加、AMP矩阵计算和decoder重计算的影响。
3. 分开比较hidden states、head logits、基座CE、当前CE、权重和未缩放梯度，确定差异最先出现的位置。
4. 只有确认误差来源和对优化步骤的实际影响，才决定修正实现、数值策略，或有依据地修订验收标准。不能为得到PASS而直接放宽阈值。

当前只确认“梯度数值门禁未通过”，尚未证明这是Dolly空答/循环的原因，也没有证实Gaussian能解决退化。
