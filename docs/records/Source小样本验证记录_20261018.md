# Qwen Source 小样本验证记录

核对日期：2026-10-18。通过 SSH 只读检查服务器的运行参数、metrics.json 和部分预测。

模型：Qwen2.5-7B-Instruct，FP16，物理 GPU 0、1，参数冻结。
源码提交：496c9ed97d0fb8bc4854ed2479259e7e9e70a790。
三个数据集分别使用原顺序前 16 条，共 48 条，仅用于流程验证。
两次运行的输入上限均为 1024，greedy、seed=42、batch size=1；生成上限从 128 调整为 512。

| 数据集 | 指标（0–1） | 128 token | 512 token | 触及上限数量：128 → 512 |
|---|---|---:|---:|---:|
| GeoSignal | ROUGE-Lsum | 0.2183997716 | 0.2035015229 | 11 → 3 |
| Dolly | ROUGE-Lsum | 0.2672988058 | 0.2689448351 | 7 → 3 |
| GSM8K | Exact Match | 0.0625 | 0.75 | 16 → 0 |

两次运行均无输入截断、无空预测。512-token 运行 complete=true，SOURCE_SMOKE=PASS。
512-token 运行峰值显存分别为 6472.0 MiB、8256.5 MiB。

128-token 结果目录：`/data/chuwenjing/results/source_smoke/qwen25-7b/20261018_103459_673103`。
512-token 结果目录：`/data/chuwenjing/results/source_smoke/qwen25-7b/20261018_110656_386331`。

实际检查到 128-token GSM8K 样本 0、1、2 在中间推导处停止；512-token 样本 0、2 已生成结论且提取正确。
原仓库 GSM8K 提取函数采用回答末尾数值：512-token 样本 1 的回答包含正确的剩余总数 23，
但最终又讨论每天卖车并以配额 50 结尾，提取结果为 50，官方口径记为错误。
该案例同时存在回答偏离问题和提取口径限制，不据此擅自把错误改为正确。
当前 0.75 是原仓库提取口径的 EM；尚未单独审查全部四个错误，也未修改评分器。

结论：加载、模板编码、生成、保存、主指标评分流程已通过小样本验证；128-token 上限确实明显影响 GSM8K。
512-token GeoSignal 和 Dolly 仍各有 3 条触及上限，应在之后比较中保留相同生成限制并记录该数量。
这些数字不构成完整论文复现结果，也不能按分数高低选择长度设置。
