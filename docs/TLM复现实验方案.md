## 1. 这轮要做什么

在已有 Source 和 TENT 实验上补齐 TLM，比较两种 3B 模型在三个数据集上的表现。新主实验统一使用Gaussian初始化；已有Kaiming运行保留为旧实现的工程对照，不填入新主实验的结果列。先通过数值预检，再完成六组固定配置实验，最后决定是否补消融和多种子实验。

论文明确规定的初始化，按论文执行；固定官方源码用于核对训练流程。两者存在差异时逐项写明，不能用“跟随默认值”代替论文要求。当前FP16硬件条件和Qwen3B规模仍与论文不同，因此本轮应称为“按论文方法开展的3B/FP16复现实验”，不能称为原条件的完全复现。

本轮采用 offline 流程：先用一组数据的全部问题做无标签适应，再用适应后的模型回答同一组问题，最后评分。参考答案只用于评分。因为适应和评测使用同一批输入，结果说明的是这种测试时适应设置下的表现；对未见问题的泛化需要另外划分数据验证。

一次全量实验包含“5000条适应＋5000条最终评测”两个阶段。评测进度中的5000是同一批问题的数量；适应时学习输入，评测时生成回答并打分。

| 模型 | GeoSignal | Dolly | GSM8K |
|---|---|---|---|
| Llama-3.2-3B-Instruct | 5000条 | 5000条 | 5000条 |
| Qwen2.5-3B-Instruct | 5000条 | 5000条 | 5000条 |

每一格都是独立实验，从原模型和新建 LoRA 开始。模型在不同数据集之间不继承适应结果。

## 2. TLM 到底训练什么

TENT 已有实现是在模型自己生成的回答上计算预测熵。这里的 TLM 则让模型学习预测输入文本的下一个 token，不需要先生成一段回答作为适应目标。

对一条问题，处理顺序如下：

1. 拼接问题和上下文，套用模型对应的提示模板。
2. 关闭 LoRA，用冻结的原模型计算输入的平均交叉熵，记为 `c0`。它反映原模型预测这段输入的困难程度。
3. `c0 > 3` 时选中该样本，权重为 `0.1 × exp(c0 - 3)`。
4. 打开 LoRA，计算当前模型在同一输入上的平均交叉熵，乘以上述权重，反向传播并更新 LoRA。

`c0` 和权重不参与反向传播。预测按因果位移计算：前一个位置预测下一个输入 token，排除 padding。

未选中的样本使用零损失，但仍保留固定官方实现的优化器调用。已有动量可能继续引起参数变化，因此“没选中”不等于“参数一定不动”。

损失和离线流程核对官方提交 `496c9ed97d0fb8bc4854ed2479259e7e9e70a790`，初始化按论文明确的Gaussian执行。可核对[官方训练配置](https://github.com/Fhujinwu/TLM/blob/496c9ed97d0fb8bc4854ed2479259e7e9e70a790/examples/train_lora/offline_ttl.yaml)和[损失实现](https://github.com/Fhujinwu/TLM/blob/496c9ed97d0fb8bc4854ed2479259e7e9e70a790/src/llamafactory/train/ttl/trainer.py)。当前启动方式以本文和运行包为准。

## 3. 本轮固定设置

| 项目 | 设置 |
|---|---|
| 数据 | 固定版本的 GeoSignal、Dolly、GSM8K，各5000条，按文件哈希核验 |
| 可训练参数 | `q_proj`、`v_proj` 的 LoRA；rank=8，alpha=16，dropout=0 |
| 初始化 | 显式 `init_lora_weights='gaussian'`，A为Gaussian、B为零；seed=42 |
| 数值类型 | 原模型FP16；LoRA参数和损失计算FP32；训练使用梯度缩放 |
| 输入长度 | 最多4096 token；超长时裁剪用户内容尾部，再重建完整模板 |
| 优化器 | AdamW，betas=(0.9, 0.999)，eps=1e-8，weight decay=0 |
| 学习率 | GeoSignal、Dolly：5e-5；GSM8K：1e-6 |
| 学习率调度 | cosine，前10%步数warmup；梯度裁剪上限1.0 |
| 训练 | 一轮，batch=1，梯度累积=1，seed=42；由Trainer采样确定访问顺序 |
| 评测 | 按原始索引，greedy生成，每条最多512个新token，使用对应模型模板和停止符 |
| 指标 | GeoSignal、Dolly：ROUGE-Lsum；GSM8K：官方提取器＋Exact Match |
| 保存 | 每25步保存完整检查点，保留最近两个；另保存100、500、1000、2500、5000步的LoRA里程碑 |

模型文件与模板清单见 [`profiles.json`](../offline_tta/tlm_offline_v4_bundle/profiles.json)，数据文件与哈希见 [`datasets.json`](../offline_tta/tlm_offline_v4_bundle/datasets.json)。服务器依赖版本由 `runtime.py` 核验，不另装一套环境。

### 与官方示例、已有TENT的差异

- **精度：** 官方示例使用BF16，现有2080 Ti使用FP16。需要关注非有限损失、梯度和实际参数更新；不能保证最终分数与BF16相同。
- **输入处理：** 固定上游处理器存在参考答案长度影响输入截断的路径。本轮先拆出纯输入文件，使训练输入不受答案内容或长度影响，并与已有Source的输入规则对齐。
- **模型规模：** 论文的Qwen主结果使用7B，本轮使用3B。Qwen3B结果单独标明规模，不能作为Qwen7B论文结果的直接复现。
- **显存处理：** 使用分块词表投影和梯度检查点，覆盖整段有效输入。CPU损失与梯度测试通过，但真实FP16梯度比较失败；目前不能认定两条数值路径已对齐。
- **初始化：** 固定官方源码调用PEFT默认的Kaiming uniform，与论文Gaussian不同。新主实验明确使用Gaussian；旧Kaiming运行归档为工程对照。Gaussian是复现配置要求，不以能否改善Dolly分数决定是否采用。
- **对比解释：** 已有TENT使用Adam和Gaussian；新TLM使用AdamW、weight decay=0和Gaussian。两套实验仍存在训练设置差异，分差不能直接解释为单独更换损失函数的效果。

## 4. 从启动到完成

运行器给每组分配一张卡，六组并行。默认卡号0到5按 Llama 的三个数据集、Qwen 的三个数据集依次分配；实际分配写在 `launch.json` 中。

```text
准备并核验输入
  → 每组真实模型预检
  → 每组16条试跑
  → 重新从原模型开始，适应5000条
  → 生成5000条回答并评分
  → 汇总Source / TENT / TLM
```

每组通过前一步才进入下一步。一组失败只停止该组，其余组继续。16条试跑的参数不会接入正式训练。

预检会检查模型和数据身份、真实参数更新、基座冻结、最长输入训练、512-token生成，以及FP16 Trainer保存和重载后的续算一致性。CPU测试通过、预检通过、全量完成是三个不同的状态。

## 5. 怎么判断有没有跑完

每组有 `preflight`、`pilot`、`formal` 三份日志。例如：

```bash
tail -n 50 "$TLM_RUN/llama3b__gsm8k_5k.formal.log"
```

适应结束后还要生成和评分。只有完整运行通过，组状态才会成为 `PASS`。最终核对下面这些文件：

| 文件 | 核对内容 |
|---|---|
| `launch.json`、各组 `*.status.json` | 实际代码快照、GPU分配和阶段状态 |
| `formal/组名/run_manifest.json` | `status=PASS`、配置及最终指标 |
| `formal/组名/training_complete.json` | `n=5000`、训练耗时、选中数量、基座未变 |
| `formal/组名/adaptation.json` | 5000条适应记录，每个原始索引访问一次；基座损失、权重、当前损失和学习率 |
| `formal/组名/tlm.jsonl` | 5000条预测，索引完整、无重复；生成长度和截断诊断 |
| `formal/组名/metrics.json` | `n=5000`；与完整预测重新计算的分数一致 |
| `formal/组名/source_reuse.json` | Source原文件哈希、输入匹配数量及预检生成样例核对结果 |
| `formal/组名/final_adapter/` | 该组最终LoRA权重 |

Source复用前会检查预测是否完整、全量输入元数据是否匹配，以及预检样例生成是否一致。不符合条件时停止，另行准备同口径Source。已有TENT的结果保留原版本身份。

### 出错和中断

先看该组 `*.status.json` 指向的日志，再看阶段输出目录里的 `failure.json`（若已生成）。保留原目录、错误信息和检查点，不通过改阈值、缩短输入或升级依赖来绕过错误。

恢复使用原代码快照和原参数，显式指定同一组的完整 `trainer/checkpoint-N`；先验证其中的 `commit.json` 和文件哈希。不要在仍运行的组上启动第二个恢复进程。具体参数见对应旧[运行包的恢复说明](../offline_tta/tlm_offline_v2_bundle/README.md#中断后的单组恢复)。该说明用于原v2任务，不用于启动Gaussian主实验。

已知的两处兼容修订是：测试不再显式传Accelerate 1.0.1不支持的 `data_seed`；旧libc没有导出 `renameat2` 时使用Linux内核接口。完整修订包已更新校验清单；再次遇到这些错误，先核对使用的包版本。

## 6. 结果怎么整理

主表每行对应一个“模型×数据集”，列出Source、TENT、TLM Gaussian、TLM相对Source的分差、相对TENT的分差，以及运行目录。Gaussian未完成时留空并标注阶段，不能用旧Kaiming分数填补。旧v1/v2另列工程对照表，注明初始化、数值路径和异常状态。统一使用百分制展示；例如77.60%到78.04%写为“提高0.44个百分点”。

另附一张成本表，记录适应耗时、最终生成耗时、峰值显存、选中率、生成长度和达到512-token上限的比例。对重复回答、分数下降和异常输出保留样例；不能只汇总提高的组。

结果交叉检查至少覆盖：数据与模型版本一致，参考答案未参与训练和选参，5000条预测完整，分数可重算，基座未更新，日志和权重能对应到同一个运行。

首轮固定seed=42，先报告观察到的分差。需要判断差异是否稳定时，再补多个种子，报告均值和波动范围。

### 首轮之后再做的实验

六组主实验完成后，结合分差和训练诊断选择有代表性的组，比较“所有输入直接训练”“只做样本筛选”“筛选并加权”。这些需要独立配置和实现核验，当前六组启动器不会自动执行。

做这些对照时统一优化器、初始化、学习率、访问顺序和数据，才能讨论输入预测、筛选与加权各自的作用。若要拆分与TENT的目标差异，也使用统一训练设置另跑对照。第一轮先不扩展7B、online或其他适应方法。

## 7. 时间和分工

六卡并行暂按3到5天预留，从正式启动算。依据是历史TENT的生成耗时：Llama＋GSM8K的5000条最终评测约22小时，其他组当时约28到53秒一条。TLM的训练和回答长度尚需实测，发生重跑或需要补Source时相应延长。

适应阶段有稳定速度、评测积累约100条后，分别估算剩余训练和生成时间。六组并行看最慢一组的结束时间，不把六组时长相加。

任务按下面四块认领，可以一人兼任，但运行和结果应由另一位成员复核：

| 工作 | 交付 |
|---|---|
| 运行维护 | 运行目录、代码身份、GPU分配、阶段状态、异常与恢复记录 |
| 方法核对 | 官方实现对应关系、损失和更新检查、与论文及TENT的差异 |
| 结果整理 | 六组主表、成本表、重算指标、正负样例 |
| 交叉复核 | 配置、数据边界、记录完整性和结论是否超出证据 |

负责人、预计日期和关联PR登记到[项目看板](../项目看板.md)。一次全量任务只指定一个启动者，避免重复占卡。
