# 六组完整评测：异常照实记录

用户要求按论文复现，不调参追分。六组各 5000 条适应已完成，继续使用现有权重、输入、生成设置和评分函数，把六组各 5000 条回答和评分做完。

先前额外的质量规则会在空答/重复增多时停止评测，本入口将其改为记录并继续。`quality_latest.json` 和报警记录仍如实写 ALERT；空答、重复、低分回答全部保留。执行完成的 PASS 只表示 5000 条评测完成，不表示质量通过或论文性能复现成功。

`continue_evaluation.py` 仅加载 final_adapter 评测，不创建 Trainer、optimizer 或 scheduler。它核验规范底模、冻结代码、训练完成记录、adapter 逐张量内容、5000 条输入、Source 和评分参考，先重放首条及最后一条已保存回答，要求 token ID 和文本一致，再追加未完成部分。已有完整预测前缀保留原字节，原失败记录归档；残缺尾部另存后才恢复边界。

为了恢复原 Trainer 准备过的模型状态，使用固定 Accelerate 1.0.1 的外层包装；记录真正进入 decoder 时的 autocast 状态，以逐 token 重放结果核验一致性，不凭包装存在与否推断。若重放或身份不一致，停止追加，不试多种精度模式挑一个结果。

`supervisor.py` 保留其余四组现有评测进程，只接续已经因质量规则退出的任务。其他异常仍阻止自动接续。每组只发起一次接续，GPU 和输出目录仍使用原有锁，避免重复写入。

训练包 v6 不变。新的统一状态目录会登记六组实际结果路径；旧控制器的失败历史保留，实时评测状态以新的 `status.json` 为准。只有六组各有 5000 条预测及对应指标，协调器才写 complete。

本入口仅补全评测，不改变已披露的 3B/FP16 复现条件差异，也不把结果下降当作必须调参修好的问题。
