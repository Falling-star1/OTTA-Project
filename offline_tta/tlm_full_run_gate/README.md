# 六组 TLM 的统一启动检查

这个脚本接管 v6 的预检结果，按三个阶段执行：

1. 等六组完整预检全部 PASS。核对同一份代码、输入、Gaussian 初始化、种子 42、CE 块大小 128、零/非零 B 梯度、最长输入训练和完整断点恢复。
2. 六组分别从底模开始，训练并生成 100 条。核对实际优化器更新、有限参数、正式学习率、100 条完整输出和质量检查。
3. 再统一检查一次所有代码、回执和试跑结果，保存 `ready_for_formal.json`，然后六组同时从底模新建 Gaussian LoRA，执行各 5000 条适应和 5000 条评测。

任一组失败，后续阶段不启动，已产生的文件保留。每个阶段启动前先串行核对六组回执，然后才创建工作进程，避免其中一组回执有问题时其他组先跑起来。单组执行时仍保留重复检查。

准备检查通过只能说明这份实现具备开跑条件；不能保证论文方法在当前模型上提高分数。正式评测仍按每 100 条检查空答、循环重复和异常相同答案，出现报警会停止该组并保留结果。

## 服务器入口

先运行固定训练包的 `check.py` 和 `launch.py --mode preflight`。运行本控制器时，`--preflights` 指向本次六组预检根目录，`--output` 必须是新的结果目录。v6 固定代码身份是：

```text
b6da067b55f5c65241ae6fbd8c706b88523f64b27dd9568ad5661255b89d7999
```

控制器参数：

```bash
python -B -u gate.py \
  --preflights "$PREFLIGHT_ROOT" \
  --expected-code b6da067b55f5c65241ae6fbd8c706b88523f64b27dd9568ad5661255b89d7999 \
  --output "$NEW_RUN_ROOT"
```

实际根目录和进程号登记在仓库实验记录。不要重复运行已有控制器，也不要把旧 v1/v2/v4/v5 的回执放进来。

查看 `status.json` 判断当前阶段：`preflight` 是完整预检，`pilot` 是 100 条验证，`formal` 才是全量。只有 `ready_for_formal.json` 存在且六个 formal 工作进程已启动，才能报告“全量在跑”。控制器最后的 `PASS / complete` 代表六组都完成；`BLOCKED` 会附上具体原因。

本脚本只依赖 Python 标准库；训练仍使用已固定的环境。本地测试：`python -B -m unittest discover -s tests -v`，当前 13 项。
