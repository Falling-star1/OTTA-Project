# GSM8K 200题配对验证

复用原2500步和三个已完成的2500步控制权重，只做推理与评分。固定seed=20261027，从原5000题中排除先前100条探针和16条故障回放后抽200题；选题不使用答案或成绩。它们仍属于原适应集合，不是新的独立测试集，也不是完整5000题分数。

注册文件先固定200题索引、排除集合、所有旧资料和四份权重哈希，才启动模型。输入与512 token贪心解码均不改。每组先精确重放原5000步2条和对应2500步已保存2条回答，再逐题原子保存预测、官方EM、开场白空壳与生成上限。Source和原5000步分数只作相同索引的补充比较，主要比较对象为同训练步数的原2500步。

代码不创建Trainer或优化器，输出必须为新目录，并取得空闲单卡GPU锁。原主实验、TENT、此前控制及故障回放目录均只读。代码、资料、输入、权重或回放不一致即保留失败，不自动改参数重跑；质量变化本身完整记录至200题。

CPU测试：`python -B -m unittest discover -s tests -v`。

入口：`evaluate.py --registration <注册文件> --registration-sha <SHA256> --mode <original_step2500或三个控制名> --output <新目录>`。

三组屏蔽目标属于方法变体，结果应报告为消融或修正版验证，不替代论文原方法，不按前缀或最高分自动选组。收齐后同时报告EM、空壳、空答、生成上限及相对原2500步的错转对/对转错。200题本身不足以认证全量达到论文90.96%。
