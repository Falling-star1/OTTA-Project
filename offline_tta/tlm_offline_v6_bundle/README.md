# TLM v6：保留原始输出层计算，分块计算交叉熵

这版解决 v3—v5 的全量前数值检查问题。原来的实现把输出层矩阵乘法也分块，显存省下来了，但反向梯度会有差异。v6 恢复一次完整的 FP16 输出层矩阵乘法，连最后一个不计损失的位置也保留，计算形状与固定的 Transformers 原始路径一致。

省显存只放在后面的交叉熵：每次处理 128 个位置的 FP32 CE，再对所有有效 token 一次求和。训练时把完整 FP16 logits 暂存在 CPU 内存，反向时逐块取回，最后把一份完整 FP16 梯度送回原始输出层。原始权重、Gaussian A/零 B、TLM 公式、阈值、学习率、样本顺序和生成设置不变。自定义 CE 只支持本实验需要的一阶反向。

## 需要通过的检查

- 固定环境的 72 项 CPU 测试。保存的全量与分块 CE、直接 logits 梯度、小模型梯度须一致，包括 padding、尾块、零权重和实际损失缩放。
- 六组真实模型分别比较 130/258/386 长度；真实最长输入较短时，使用预先记录的实际长度。Gaussian 初始零 B 和临时非零 B 均检查，保留原 atol=1e-5、rtol=1e-2、逐参数 relative L2≤1%。记录完整输出层形状、FP16 dtype、dlogits 和所有 LoRA 梯度。
- 原来的 16 步中断恢复检查，核对 adapter、optimizer、scheduler、RNG 和 GradScaler。
- 最长输入再走 16 步实际混合精度 Trainer，使用该任务正式学习率，强制选中仅用于测试资源和更新；检查有效更新、有限 optimizer/adapter、冻结底模、初始 adapter 恢复和峰值显存。
- 底模生成须与已保存 Source 一致；随后六组分别训练并生成 100 条，全部通过再启动全量。

独立诊断中，六组严格梯度检查均通过，已测 LoRA 梯度最大差值为 0；最长输入实际 Trainer 的显存峰值约 8.0 GiB。这个结论属于独立诊断，**不能替代本冻结包自己的完整预检和 100 条验证**。实时状态写在仓库外部实验记录，不修改这份冻结包。

## 运行顺序

先激活 `/home/chuwenjing/TTA_LLM/TLM/local_repro/stage1/activate_tlm.sh`，运行本包 `python -B check.py`。随后只运行 `launch.py --mode preflight`。六张卡按 Llama Geo/Dolly/GSM、Qwen Geo/Dolly/GSM 分配，每组独占一张卡。

全量由相邻的 `tlm_full_run_gate/gate.py` 控制：六组完整预检 → 六组各 100 条 → 核验全部结果 → 六组各 5000 条。每个阶段有任一组失败，就保留日志、权重和预测，停止后续阶段。**不要使用本包旧的 `launch.py --mode all` 入口：它保留了旧的 16 条试跑流程。**

正式训练从底模重新初始化 Gaussian LoRA，不从 100 条试跑权重续训。每组只训练 5000 条输入一遍，再生成同样 5000 条；标准答案仅用于评分。完整 Trainer 检查点每 25 步保存、保留最近两个，另存 100/500/1000/2500/5000 步 adapter。出现中断，必须明确指定本次运行自己的检查点，不能混用旧版输出。

## 与原文的条件差异

这是 3B 模型、2080 Ti FP16 条件下的方法复现。论文中的 Qwen 模型规模和官方 BF16 硬件示例不同；输入截断使用不依赖标准答案的规则。CPU 暂存 logits 是省显存措施，不是论文新增模块。Source 生成仍按原有 FP16 整块路径执行。

通过检查说明工程实现和已测输入可用，不保证整套 5000 条结果一定优于 Source。全量期间继续按每 100 条输出检查空答、循环重复和异常相同回答，报警后保存结果并停止该组评测。
