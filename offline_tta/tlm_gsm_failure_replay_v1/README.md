# GSM8K 实际故障回放

前一轮8条生成没有覆盖“只说推理开场白”的故障。本入口从原5000步实际350条空壳回答中，用固定种子314159抽16条，逐项重放其原回答，再对原2500步及三个2500步控制权重做配对推理。选择不使用正确答案或分数。

这是故障集合上的诊断，不是随机测试分数。不能将16条正确数当作全量准确率，也不能据此挑选正式方法或宣称已复现论文90.96%。三组控制改变了训练目标，与原文基线单独保留。

入口没有Trainer、训练或优化器创建。输出必须为新目录，必须使用空闲的单张物理GPU并取得既有GPU锁。验证原预测、模型、输入、Source和参考值哈希；控制必须已完成且轨迹核查通过，final adapter逐张量等于完整2500步检查点。原5000步权重必须精确重放所选16条token和文本，才评测目标权重。

CPU检查：`python -B -m unittest discover -s tests -v`。

运行参数：`replay.py --runtime <固定v6目录> --original <原Llama-GSM目录> --control-root <三组控制目录> --mode <original_step2500或控制名> --adapter-sha <注册SHA256> --output <新目录>`。使用同一Accelerate FP16推理包装、512 token贪心生成与固定官方答案提取函数；每条回答及时保存。
