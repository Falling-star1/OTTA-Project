# 中期实验方案

> 本文合并数据协议、baseline、评测设置和论文复现策略，是中期实验的唯一规则来源。

## 1. 实验问题

1. LoRA 在线适应相较 No Adaptation 是否改变后续测试性能？
2. High-PPL 是否优于 Random？
3. OTTA v0 是否提供区别于 PPL 的选样信号？
4. OTTA 的性能收益是否值得额外梯度计算成本？

## 2. 在线协议

```text
当前 batch 先预测并保存结果
  -> 隐藏标签
  -> 仅根据无标签输入选样和更新
  -> 更新后的模型仅影响后续 batch
```

标签只由 evaluator 在预测保存后读取，不进入 prompt、适应 loss 或选择器。

## 3. 默认配置

| 项目 | Smoke test | 主实验 |
|---|---:|---:|
| 模型 | Qwen2.5-0.5B-Instruct（首选） | 与 smoke 相同 |
| 数据集 | ARC-Challenge 固定子集 | ARC-Challenge 固定子集 |
| 样本数 | 32 | 200 |
| batch size | 8 | 8 |
| 每批选择 k | 2 | 2 |
| seeds | 42 | 42、43、44 |
| LoRA rank / alpha | 8 / 16 | 8 / 16 |
| LoRA dropout | 0 | 0 |
| target modules | q_proj、v_proj | q_proj、v_proj |
| optimizer / lr | AdamW / 1e-4 | 相同 |
| betas / eps | 0.9、0.999 / 1e-8 | 相同 |
| weight decay | 0 | 0 |
| 每 batch 更新步数 | 1 | 1 |
| max input length | 256 tokens | 256 tokens |

硬件不足时降到更小 causal LM；一旦主实验开始，四种方法必须使用同一模型、精度和 revision。

## 4. 数据协议

标准样本格式：

```json
{
  "sample_id": "arc_challenge_0001",
  "question": "Question text",
  "choices": [
    {"label": "A", "text": "Choice A"},
    {"label": "B", "text": "Choice B"}
  ],
  "answer": "B"
}
```

- adaptation view：`sample_id/question/choices`；
- evaluation view：预测保存后额外读取 `answer`；
- 截断后若题干或任一选项不完整，丢弃并记录原因；
- 每个 run 保存实际 sample_id 顺序，不能只保存 seed。

## 5. 预测与适应目标

预测：对每个候选选项计算条件 token-average log-likelihood，选择最高者。

适应：将题干和全部选项格式化为不含答案的文本，计算 token-average causal-LM NLL。所有适应方法共用同一 loss。

## 6. 必做方法

| 方法 | 选择规则 | 是否更新 | 作用 |
|---|---|---:|---|
| No Adaptation | 无 | 否 | 原模型参照 |
| Random | 固定 seed 均匀随机 | 是 | 随机下界 |
| High-PPL | token-average NLL top-k | 是 | 难度选样对照 |
| OTTA v0 | AdamW 预条件方向余弦 top-k | 是 | 项目方法 |

只有主表完成后才增加 OTTA-raw。Verifier、完整 TLM/VDS-TTT、随机投影和第二数据集不在中期必做范围内。

## 7. 公平性

- 每种方法从相同 checkpoint 和相同初始 LoRA 独立启动；
- 测试流顺序、batch size、k、学习率和更新步数一致；
- Random 只由 run seed 决定；
- 不从前一种方法继承 LoRA 或 optimizer 状态；
- 不根据主实验标签选择超参数；
- 失败运行同样保存配置、日志和已完成输出。

## 8. 指标

| 类别 | 指标 |
|---|---|
| 主指标 | Online Accuracy、相对 No Adaptation 的百分点变化 |
| 效率 | 推理/选择/更新时间、总时长、峰值显存 |
| 机制 | OTTA 与 High-PPL 重合率、utility-PPL 相关、fallback 次数 |
| 过程 | 累计 accuracy、滑动窗口 accuracy、选样分歧案例 |

## 9. 输出契约

```text
artifacts/runs/<method>/<seed>/<timestamp>/
├─ config.json
├─ environment.json
├─ predictions.jsonl
├─ selections.jsonl
├─ metrics_by_batch.jsonl
├─ summary.json
└─ run.log
```

## 10. 论文复现边界

中期采用自建统一 runner：从 TLM 借鉴无标签 NLL、High-PPL 和 LoRA 流程，从 OPUS 借鉴 optimizer-aware 思想。不得将 High-PPL baseline 写成“完整复现 TLM”，也不得把 OTTA 写成“完整迁移 OPUS”。

论文仓库代码阅读每篇最多半天；若没有直接形成公式修订、测试或实现决定，就返回主线开发。

## 11. 验收标准

Smoke test：四种方法均精确处理 32 条样本，输出齐全，无 NaN/Inf，适应方法每批选择 k 个样本。

主实验：四种方法 × 三个 seeds 完成；结果可由 JSONL 重算；主表报告均值和标准差；无论正负结果，都有日志支持的机制或失败分析。
