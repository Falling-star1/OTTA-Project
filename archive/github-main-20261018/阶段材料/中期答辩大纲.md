## 第 1 页：题目与一句话问题

**题目：** 面向大模型测试时自适应的高效且简单的数据选择机制

**一句话：** 测试时更新预算有限，应该选择哪些无标签输入更新模型？高困惑度不一定意味着对当前优化器真正有用。

## 第 2 页：研究背景

- 部署分布会变化，完全重新训练成本高；
- TTA 在测试期间利用无标签输入轻量更新；
- LLM 场景通常只更新 LoRA；
- 不是所有测试样本都值得消耗一次反向传播。

## 第 3 页：相关工作与缺口

| 方法类别 | 代表思路 | 项目观察 |
|---|---|---|
| 难度选样 | High-PPL / TLM 风格 | 难可能来自噪声 |
| verifier 选样 | VDS-TTT | 需要额外模型 |
| optimizer-aware | OPUS | 面向预训练，尚需迁移到在线 TTA |

落脚句：现有 LLM-TTA 选样较少显式利用当前 AdamW 状态。

## 第 5 页：OTTA v0.2

展示三个公式：

```text
u_i   = g_i / (sqrt(v_hat_t) + eps)
d_ref = m_hat_t / (sqrt(v_hat_t) + eps)
score = cosine(u_i, d_ref)
```

解释：在统一的 AdamW 预条件空间中，选择与历史有效更新方向更一致的样本。

## 常见追问

### 为什么和历史方向一致就是有用？

这是项目检验的假设，不是先验真理。主实验和滑动窗口分析用于验证；方向锁定是已知风险。

### 与 OPUS 有什么区别？

OPUS 面向预训练并使用 proxy 分布；本项目面向无标签在线 TTA，用历史 AdamW 有效方向作为轻量参考，不声称完整复现 OPUS。

### 是否使用了测试标签？

标签只在当前 batch 预测保存后由 evaluator 计算 accuracy，不参与 prompt、选样和更新。

### 为什么不用 7B？

中期先验证方法机制和工程闭环。模型规模是后续扩展维度，不影响当前对四种选择策略的受控比较。

### 如果 OTTA 没有提升怎么办？

报告负结果，并通过选样重合率、方向分布、后续窗口表现和额外成本判断假设为何不成立，而不是隐藏实验。
